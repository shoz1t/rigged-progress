# RIGGED: ход разработки

Публичный сайт прогресса разработки игры RIGGED (ShozitDev): вехи, задачи, тесты, известные проблемы, журнал изменений. Простые HTML/CSS/vanilla JS, без фреймворков, трекеров и сторонних CDN. Шрифты Spectral и Golos Text (SIL OFL 1.1) лежат в `assets/fonts/` вместе с лицензиями.

Исходный код игры и сюжетные подробности здесь не публикуются: в данных только нейтральные названия. Внутренние имена документов и хэши коммитов обобщаются до «внутренний документ», «ревью критика», «коммит».

Сайт: https://shoz1t.github.io/rigged-progress/

## Как устроены данные

`data/progress.json` — единственный источник для сайта. Его не правят руками: он генерируется.

- `tools/sync_progress.py` собирает JSON из внутренних источников проекта: roadmap (вехи и пакеты), вердикты в ревью `docs/build/*REVIEW*.md`, история git кода и документации, состояние рабочего дерева.
- Правила статусов: **completed** только если в ревью найден вердикт PASS; есть незакоммиченная работа по пакету — **in_progress**; реализовано, но PASS нет — **testing**; иначе **planned**. Даты берутся из ревью или git, коммиты проверяются.
- `data/overrides.json` — единственное, что пишется вручную: публичные названия и описания, приоритеты, тесты, известные проблемы, текст журнала. Привязка пакетов к ревью, ссылки на коммиты и документы лежат в локальном `data/private/private.json` (не коммитится).
- Правила статуса: PASS «с исправлениями» без повторной проверки (`fixes_unverified`) даёт `testing`, а веха помечается неточной.
- `scripts/stopwords.py`: список сюжетных терминов; `validate.py` роняет workflow, если термин, хэш коммита или `spoiler_detail` попали в публичные данные. Новый пакет из roadmap без записи попадает на сайт нейтрально («Описание ещё не опубликовано», помечен неточным).
- Приватность: итог строится по списку разрешённых полей, каждая строка проверяется на абсолютные пути, почту, токены, идентификаторы поставщиков (`scripts/privacy.py`). Нашлось что-то — генерация падает с кодом 2 и ничего не пишет.

## Обновление

```
tools/publish_progress.sh        # sync, валидация, скан, commit data/, push main, ожидание workflow
tools/check_drift.sh                      # проверить, что данные актуальны (код 3 = отстали)
```

После push в `main` GitHub Actions (`.github/workflows/deploy.yml`) запускает `scripts/validate.py` (схема без внешних библиотек), `scripts/scan_private.py`, `scripts/build.py` (копия в `_site/`, статичная сводка для `<noscript>`) и публикует на GitHub Pages. Запускается и вручную (`workflow_dispatch`).

Корень проекта игры по умолчанию соседний каталог `../rigged`, либо переменная `RIGGED_ROOT`.

## Локальный просмотр

```
python3 scripts/build.py && python3 -m http.server -d _site
```

Пути на сайте относительные, он работает под `/rigged-progress/`. Исключение: `404.html` использует абсолютный базовый путь.
